Various training and fine-tuning methods aim to achieve the goal of \term{value-alignment}; however, their effectiveness cannot be easily measured. As discussed in \ref{sec:values}, this is due to values being latent objects and not directly measurable. To measure value alignment we need to use indirect techniques. A common method of indirect evaluation is to probe for situations where the target \term{agent} is forced to make a decision from which we can then infer the values that they hold. This chapter is about exactly this: using social/ethical \term{dilemma}s as an indirect measurement tool for the values that a model—and any agent built on it—holds. Because of the gap between observed values and actual behaviour, these dilemmas provide a useful tool for getting the public's direct preference on specific value-laden decisions; this is explored in the next chapter.

In \ref{chap:finetuning} an LLM was fine-tuned on value survey data. An implicit assumption in \rqref{align} is that a model's values determine its behaviour. We can therefore test indirectly whether those values have changed by testing the model's behaviour. The behaviour of the model can be measured as the action it took when given a dilemma. By quantitatively comparing the base model and the fine-tuned model we can see if the behaviour differs. If this is true, it supports the notion that the fine-tuning process has instilled different values into the models and so, when in a new situation, the model will behave differently (as values drive behaviour) \cite{schwartzOverviewSchwartzTheory2012}.

To test the models' behaviour and whether it changes with fine-tuning, we developed a set of 30 dilemmas spanning 10 different AI agent work profiles (\term{work-profile}s). We gave the models the dilemmas and generated responses. These responses were classified by an LLM-as-judge to allow for quantitative comparison between the base and fine-tuned models. The quantitative analysis (that was pre-registered \cite{thompsonPreregistrationAligningLLMs2026/10/1515:17}) demonstrated significant divergence in response patterns between the base and fine-tuned models. This was not consistent across all dilemmas, with only 18 showing a significant divergence between the base and fine-tuned models.

The structure of the chapter is as follows. In \ref{sec:dilemmas-methods}, the methods of writing dilemmas, running the experiments and categorising the responses are discussed. In \ref{sec:dilemmas-analysis}, the methods of analysing the model responses are discussed. Finally, in \ref{sec:dilemmas-results}, the results of the analysis are presented.

\section{Hand-crafted dilemmas to test model behaviour}
\label{sec:dilemmas-methods}

Using dilemmas to test behaviour and infer values is a common method \cite{EthicalDilemmasOverview,chiuDailyDilemmasRevealingValue2025,lourieScruplesCorpusCommunity2021,hendrycksAligningAIShared2023,scherrerEvaluatingMoralBeliefs2023}. Because we are testing the behaviour of the model with the goal of value alignment with the New Zealand public, we needed to write specific dilemmas that capture the New Zealand context as well as specific deployment contexts. Existing dilemma datasets focus on more general social situations \cite{lourieScruplesCorpusCommunity2021,chiuDailyDilemmasRevealingValue2025} or on contrived ethical and value judgements \cite{hendrycksAligningAIShared2023,scherrerEvaluatingMoralBeliefs2023,awadMoralMachineExperiment2018}; none is grounded in New Zealand deployment contexts. Taken together, our 30 dilemmas create a behavioural test of the model's values that spans contrived ethical trade-offs (from trolley-problem-esque cases to everyday social questions). By sampling many responses from the model for each dilemma, we can gain confidence in the model's response patterns. By classifying these responses, we can then quantitatively compare the behaviour of the base and fine-tuned models.

The full pipeline, from the inputs through to the three measurements taken from the responses, is shown in \figref{dilemmas-pipeline}. The pipeline has three components. The \texttt{choice judge} is a simple classification task that sorts each response into one of the two answer categories (or a catch-all \texttt{Other} category). The embedding model allows for numerical analysis of answer similarity—which turned out not very useful. Finally, the \texttt{quality judge} scores each index-matched base–fine-tuned-model response pair on value divergence, survey quality and interest to the New Zealand public. Each of these components is discussed in later sections \ref{subsec:dilemmas-classify,subsec:dilemmas-quality}, with the embedding deferred to the appendix due to its reduced utility \ref{subsec:dilemmas-embedding}.

\cdiagram{dilemmas-pipeline}{The dilemma pipeline. Each dilemma is paired with a work-profile system prompt and answered by the base model or one of the fine-tuned models; the sampling parameters and response details are in \ref{sec:dilemma-run-parameters}.}

\subsection{Behavioural tests as single-response agentic dilemmas}

Each dilemma is a single message sent to the model. A dilemma combines a \termref{work-profile} (the system prompt) and a situation (the user prompt). This is given to the model and responses are sampled, relying on the stochasticity of the model to give different responses each time. 

The reason for testing with dilemmas is that we are checking model responses in an out-of-distribution setting, so that we can see if the fine-tuning transfers. This means that we are not just testing the model on different questions but in a completely different situation. To mimic a deployment context, the system prompts framed the context to be realistic, like what an agent would see. This means the system prompt includes a description of where the agent is (i.e., an AI agent deployed here) and what it is doing (this part is shared across all work profiles), as well as reference documents (real codes of conduct, legal acts and policy documents). An attempt was made to minimise value instructions (e.g., being kind) to ensure that any judgements reflect the model's own values or interpretations of official documents.

To ensure that each model responded in a way that suits the survey, a standard response format was added near the front of the system prompt. The exact wording was:

\begin{quote}
``You will be given a situation and asked what you would do. Answer in no more than two short sentences (about 40 words). Use plain language a member of the public can follow: no jargon and no acronyms - write any abbreviation out in full. Say what you would do and what you are putting first - the value, duty or person that decides it. Do not describe procedures, steps or policy. You cannot take actions, ask questions, or look anything up.''
\end{quote}
\noindent The response format does make the task more contrived; however, in \ref{sec:situational-awareness} a situational-awareness test was conducted. The results show that the models are generally unaware of their environment, which is consistent with their responding to the system prompt and not overtly \scare{gaming the system}.

\subsection{Writing dilemmas to test model behaviour}

Given the goal of aligning a model with the New Zealand public, it was important that the dilemmas used were relevant to the New Zealand context. Given the lack of previous work on New Zealand-specific, deployment-grounded dilemmas, a new dataset was needed. Previous attempts to create more complex agentic simulations proved too difficult to get clean differences of value-based decisions (see \ref{app:simulation}). Therefore, when writing the dilemmas, it was important to ensure that the value trade-off being tested was clear and unambiguous to a general audience.

Ten different \termref{work-profile}s were created with three dilemmas each. Each dilemma was a variation of a similar trade-off. The profiles, their reference documents and the thirty dilemmas are listed in \ref{sec:dilemma-profiles}. The decision about which work profile to use was based on two things:
\begin{enumerate}
    \item Deployment contexts that could plausibly exist in the future and that cover a wider range than simply chatbot assistants.
    \item A work profile that has the potential to create high-quality dilemmas (easy to read, with each option equally defensible).
\end{enumerate}

An example of one of the written dilemmas is shown in \figref{dilemma-example}.

\cdiagram[htbp]{dilemma-example}{An example dilemma from the incident-response work profile. The model receives the work profile as a system prompt and the situation and question as a user prompt. The answer categories are not shown to the model; the choice judge uses them to classify the response.}

Many dilemmas and work profiles were brainstormed by us with support from Ben Cravens and AI agents. Whether the work profiles had sufficient coverage of the New Zealand context was a human judgement call. Each dilemma also had to be readable, which was determined through feedback from the research team (James Thompson, Ben Cravens, Ali Knott and Andrew Lensen). Lastly, the dilemmas had to be decisive, meaning that each of the answer options should be equally defensible, otherwise the fine-tuned model was unlikely to diverge. This was checked by passing the dilemmas through several frontier models and checking that they gave divergent responses. If all models gave the same response, the dilemma was revised, although perfect balance was not always achievable. This frontier-model spot check was important because even when the research team thought a dilemma seemed balanced, the models sometimes agreed perfectly.

The actual writing process was done in three stages. Firstly, four work profiles were developed and one dilemma was written for each of them. These were iterated on until they were high quality. Next, frontier AI models were used to generate additional situations and work profiles. The generated ones were manually filtered and then iterated on until the target number of 10 work profiles with 3 dilemmas each was reached.

Importantly, all of this iteration of the work profiles and situations was done prior to testing the actual base and fine-tuned models to prevent any cherry-picking of dilemmas that would show divergence. The goal was to create a set of dilemmas that were balanced and would be able to show divergence if it existed, not to create dilemmas that would show divergence.



\section{Analysis}
\label{sec:dilemmas-analysis}

This chapter asks whether the fine-tuned models are behaviourally different from the base model, and which dilemmas are most useful for comparing them in the public survey.

\subsection{Classifying the model responses with a judge model}
\label{subsec:dilemmas-classify}

Before any quantitative analysis can take place, each response has to be classified into one of the two answer categories (or the catch-all \texttt{Other}). An LLM-as-judge model (\judgemodel{}) was used for this classification, which was selected due to its trade-off between capabilities and cost \cite{IntelligenceIndexVs}. The judge was given the situation, the question, the answer options, the model's response and reasoning. The categories are the two answer options written into each dilemma. Standard LLM-as-judge methods were used \cite{zhengJudgingLLMasaJudgeMTBench2023, liuGEvalNLGEvaluation2023, guSurveyLLMasajudge2026}: structured output against a fixed answer schema and a temperature of 0. The judge does not have access to the model's system prompt, so it cannot use its knowledge of the work profile to classify the response. Bias stemming from the LLM-as-judge is not expected to be significant due to the simplicity of the classification task.

In \figref{dilemma-response-categories} we can see three responses to the example dilemma in \figref{dilemma-example}, one for each category used by the choice judge.

The third response is competent, but it proposes a third action—cutting the specific connection rather than either listed option—so the judge places it in \texttt{Other}.}



\subsection{Using a Monte Carlo permutation test to measure divergence}
\label{subsec:dilemmas-permutation}

As specified in the pre-registration \cite{thompsonPreregistrationAligningLLMs2026/10/1515:17} (the analysis plan lodged before data collection), the model response classifications were analysed using a Monte Carlo permutation test to measure the significance of the divergence between the base and fine-tuned models.

The test of divergence for each dilemma was performed by taking the counts of each model's response classifications (e.g., Model A had 24 option A, 23 option B and 3 other, while Model B had 12 option A, 15 option B and 3 other) and calculating the total variation distance (TVD) between the two distributions. This is a one-sided test; the null hypothesis is that the observed variation in TVD is due to chance. To build the null distribution for each dilemma, the counts are pooled and 10,000 permutations are drawn that assign the model labels randomly to each response. To calculate the p-value for each dilemma, we count how many of the permutations have a TVD greater than or equal to the observed TVD. The p-value is then calculated as follows:

\begin{align}
    p_d = \frac{1 + \#\{r : \mathrm{TVD}^{*}_{d,r} \ge \mathrm{TVD}_d\}}{10{,}001}
\end{align}

\noindent Here, $\mathrm{TVD}_d$ is the observed TVD for dilemma $d$, $\mathrm{TVD}^{*}_{d,r}$ is the TVD for dilemma $d$ in the $r$-th permutation and $\#$ is the count of elements in a set.


The overall test of divergence ($p_{\text{overall}}$) between the base model and the fine-tuned model involves counting how many times one of the 10,000 permutations has a mean divergence greater than or equal to the observed mean divergence. This gives a p-value for the overall test of divergence.
\begin{align}
    \overline{\mathrm{TVD}} &= \frac{1}{30}\sum_{d=1}^{30} \mathrm{TVD}_d\\
    \overline{\mathrm{TVD}}^{*}_r &= \frac{1}{30}\sum_{d=1}^{30}\mathrm{TVD}^{*}_{d,r}\\
    p_{\text{overall}} &= \frac{1 + \#\{r : \overline{\mathrm{TVD}}^{*}_r \ge \overline{\mathrm{TVD}}\}}{10{,}001}
\end{align}

\noindent Note that, due to the nature of the permutation test, the p-value is bounded by the number of permutations. In this case, with 10,000 permutations, the p-value is bounded at $1/10{,}001 \approx 0.0001$.

The p-values are then corrected to control the false discovery rate when performing multiple significance tests using the Benjamini-Hochberg procedure \cite{benjaminiControllingFalseDiscovery1995}. The per-dilemma p-values are corrected within a model across the 30 dilemmas; the overall p-values are corrected across the four models.

There are technically three response options for each dilemma; the third is a catch-all for responses that cannot be mapped to either main category. The \texttt{Other} category is uninformative for comparing the two models, so a sensitivity analysis was done to see whether the results change when it is included or excluded.

Importantly, this method does make assumptions. For the per dilemma test the responses from the two models must be exchangeable, and the individual samples must be independent. For the overall test, there is an additional assumption that the dilemmas are independent of each other. This assumption is not fully met, because some dilemmas share the same work profile and describe similar situations with different details. Additional profile-sensitivity checks were done to see if the results change when the dilemmas are grouped by work profile.

\subsection{LLM-as-judge scoring of the potential comparisons}
\label{subsec:dilemmas-quality}

Given the use of the comparisons in \ref{chap:survey}, it was important to have a measure of the quality of the comparisons. Comparing almost identical responses would not be interesting, and neither would comparing models that made similar decisions. We used an LLM-as-judge ensemble to develop a scoring system for measuring the quality of the comparisons. Each judge was given a prompt that included the dilemma, the base model response and the fine-tuned model response. Each judge was then asked to score the value divergence (among other things) on a scale of 1--5. The prompt can be seen in \ref{sec:dilemma-judge-prompt}.

As there was more room for interpretation and bias in this task, an ensemble of three models was used: \modelref{gpt-6-luna}, \modelref{claude-haiku-5.5} and \modelref{deepseek-v4.1-flash}.

\figref{dilemma-divergence-examples} shows a low- and a high-divergence pair from the same dilemma.

\cdiagram[htbp]{dilemma-divergence-examples}{Low and high value-divergence pairs from the same dilemma, the incident-response breach in \figref{dilemma-example}. Each pair shows the base-model response and the modal fine-tune's response. The low pair is scored 1/5: both models refuse to shut down. The high pair is scored 5/5: the base model refuses, while the modal fine-tune chooses to shut down. Scores are the mean of the three quality judges.}

When generating the comparisons for the survey, only sample-index-matched pairs were used. This decision was made because the cross product of all responses would be too large and would include duplicate responses. Therefore, some pairing is needed, and index matching is the most straightforward method, even if it is arbitrary. This was pre-registered to prevent cherry-picking pairs, given that one could reasonably pair one sample with any of the 50 samples from the other model.

\label{sec:dilemmas-results}

The two most important results are which model diverges most from the base model and which dilemmas are most useful for the public survey.


\subsection{All models are divergent yet some more than others}

Four different fine-tuned models were tested against the base model. In \tabref{dilemmas-h1-summary}, we can see that three of the four models have a similar level of divergence from the base model. The \modelref{ft-modal} stands out as having the largest divergence from the base model. Given the pre-registered hypothesis \cite{thompsonPreregistrationAligningLLMs2026/10/1515:17} and analysis plan, this supports H1, which addresses \rqref{align}; the survey tests whether the change is in the preferred direction. The training on the survey data has created models that are sufficiently different in behaviour from the base model. Given that these models were only trained on abstract survey data and not on the dilemmas themselves, this is consistent with emerging evidence \cite{nieSurveytoBehaviorDownstreamAlignment2025}. It supports the notion that the fine-tuning process has instilled different values into the models and so, when in a new situation, the model will behave differently (as values drive behaviour).

By inspecting \tabref{ft-results-Qwen3.8-27B}, we can see that the \modelref{ft-modal} has the highest training accuracy yet also the highest cross entropy and KL divergence on the WVS items. It fits the training data almost perfectly and moves the probability mass the most. A plausible explanation is that this is why it has the most divergent behaviour from the base model.

On the other hand, the \modelref{ft-first-token} performs among the best on the training metrics (highest validation accuracy and lowest validation cross entropy) yet has the least divergence from the base model. There are a few possible explanations for this. One is that, given the probability mass has moved less than the other models, its responses are more likely to be closer to the base model \footnote{It isn't necessarily the case that this is a bad thing. It is quite plausible that the optimal response is one very close to the base model and so the other models are overfitting to the training data and moving away from the optimal response.}. The reduced amount of probability mass moved is due to the training objective—a real distribution—being close to the base model (whereas the \modelref{ft-modal} is training to meet a one-hot encoded distribution) and to the first-token target providing less supervision per example than a full response string.

\subsection{Only some dilemmas are decisive}

The difference shown in \tabref{dilemmas-h1-summary} is an average across all dilemmas. In \tabref{dilemmas-modal-quality}, we can see, however, that 12 of the 30 dilemmas (40\%) have no statistically significant difference between the base model and the most divergent fine-tuned model after Benjamini-Hochberg correction.

\section{Conclusion}

This chapter tested whether the fine-tuned models behave differently from the base model on 30 hand-written dilemmas. All four fine-tuned models diverged from the base model, with the modal fine-tune diverging most. This supports H1, which addresses \rqref{align}. For that model, 18 of the 30 dilemmas showed a statistically significant difference. The same dilemmas and the judge's value-divergence scores were then used to select the comparisons for the public survey.

The result that the models diverge in behaviour is limited in two ways. First, with only 30 unique dilemmas across 10 work profiles, the claim is limited to these dilemmas. Second, sampling noise remains because the number of responses per dilemma is finite (see \ref{sec:dilemma-run-parameters}). Larger samples would increase confidence. Increasing both the number of dilemmas and the number of responses would strengthen the results, but the time and resource constraints of this project did not allow this.

There are some further methodological limitations worth noting: errors in the classification of model responses, the contrived nature of the dilemmas (i.e., they are not real deployment contexts), and the \term{value-action-gap}, which means the value shift is measured indirectly through a noisy proxy.

The next chapter uses the 18 significant dilemmas and the most divergent fine-tuned model to test whether the public prefers the fine-tuned model over the base model.
