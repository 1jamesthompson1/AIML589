Various training and fine-tuning methods exist to try to achieve the goal of \termref{value-alignment}; however, their effectiveness cannot be easily measured. As discussed in \ref{sec:values}, this is due to values being latent objects and not directly measurable \cite{schwartzOverviewSchwartzTheory2012}. To measure value alignment we need to use indirect techniques. A common method of indirect evaluation is to probe for situations where the target \termref{agent} is forced to make a decision from which we can then infer the values that they hold. This chapter is about exactly this: using social/ethical \term{dilemma}s as an indirect measurement tool for the values that a model—and any agent built on it—holds.

In \ref{chap:finetuning} an LLM was fine-tuned on value survey data. An implicit assumption made in \rqref{align} is that the values of a model will determine the behaviour of the model. Therefore, we can indirectly test whether the values of the models have changed by testing the behaviour of the models. The behaviour of the model can be measured as the action it took when given a dilemma. By quantitatively comparing the base model and the fine-tuned model we can see if the behaviour differs. If this is true, it supports the notion that the fine-tuning process has instilled different values into the models and so, when in a new situation, the model will behave differently (as values drive behaviour) \cite{schwartzOverviewSchwartzTheory2012}.

To test the models' behaviour, a set of 30 dilemmas was developed, spanning 10 different AI agent deployment scenarios (\termref{work-profile}s). The models were given the dilemmas, and responses were generated. These responses were classified by an LLM-as-Judge to allow for quantitative comparison between the base and fine-tuned models. The quantitative analysis demonstrated significant divergence in response patterns between the base and fine-tuned models. The results are used in \ref{chap:survey} to ask the public to directly choose between pairs of model responses to dilemmas. This survey will test whether the value change was in the correct direction. In this way, we can test the value alignment of the fine-tuned models with the New Zealand public without having to directly measure or define the values of the model or the public.

Initially, the methodology of this chapter was going to test the model using agentic dilemmas (i.e., behavioural simulations); however, this proved too difficult to get clean divergent value judgements between models. Therefore, a soft pivot was made to single-response dilemmas. More information about the agentic dilemmas can be found in \ref{app:simulation}—it was a better methodological approach, yet in practice it was too difficult to implement.

The structure of the chapter is as follows. In \ref{sec:dilemmas-methods}, the methods of writing dilemmas, running the experiments and categorising the responses are discussed. In \ref{sec:dilemmas-analysis}, the methods of analysing the model responses are discussed. Finally, in \ref{sec:dilemmas-results}, the results of the analysis are presented.

\section{Hand-crafted dilemmas to test model behaviour}
\label{sec:dilemmas-methods}

Using dilemmas to test behaviour and infer values is a common method \cite{EthicalDilemmasOverview,chiuDailyDilemmasRevealingValue2025,lourieScruplesCorpusCommunity2021,hendrycksAligningAIShared2023,scherrerEvaluatingMoralBeliefs2023}. As we are testing the behaviour of the model with the goal of value alignment with the New Zealand public, specific dilemmas needed to be written to capture the New Zealand context as well as specific deployment scenarios. Previous dilemma datasets focus on more general social situations \cite{lourieScruplesCorpusCommunity2021,chiuDailyDilemmasRevealingValue2025} or contrived ethical and value judgements \cite{hendrycksAligningAIShared2023,scherrerEvaluatingMoralBeliefs2023,awadMoralMachineExperiment2018}. These dilemmas together create a behavioural test of the model's values. The base model and each of the four fine-tuned models were given the dilemmas, and responses were generated. By running the model many times through the dilemmas, we can gain confidence in the model's response patterns. By grouping these responses, we can then quantitatively compare the behaviour of the base and fine-tuned models.

\subsection{Behavioural tests as single-response agentic dilemmas}

Each dilemma is a single message sent to the model. A dilemma is made up of a system prompt (that constitutes the \term{work-profile}) and a user prompt (that is called the situation). This is given to the model and responses are sampled, relying on the stochasticity of the model to give different responses each time.

The reason for testing with dilemmas is that we are checking model responses in an out-of-distribution setting, so that we can see if the fine-tuning transfers. This means that we are not just testing the model on different questions but in a completely different situation. To mimic a deployment scenario, the system prompts framed the context to be realistic, like what an agent would see. This means the system prompt includes a description of where the agent is (i.e., an AI agent deployed here) and what it is doing (this part is shared across all work profiles), as well as reference documents (real codes of conduct, legal acts and policy documents). An attempt was made to minimise value instructions (e.g., being kind) to ensure that any judgements reflect the model's own values or interpretations of official documents.

To ensure that each model responded in a way that suits the survey, a standard response format was added near the front of the system prompt:

\begin{quote}
You will be given a situation and asked what you would do. Answer in no more than two short sentences (about 40 words). Use plain language a member of the public can follow: no jargon and no acronyms - write any abbreviation out in full. Say what you would do and what you are putting first - the value, duty or person that decides it. Do not describe procedures, steps or policy. You cannot take actions, ask questions, or look anything up.
\end{quote}
\noindent The response format does make the task more contrived; however, in \ref{subsec:situational-awareness} a situational-awareness test was conducted. The results show that the models are generally unaware of their environment, which is consistent with their responding to the system prompt and not overtly \scare{gaming the system}.

\subsection{Writing dilemmas to test model behaviour}

Given the goal of aligning a model with the New Zealand public, it was important that the dilemmas used were relevant to the New Zealand context. Given the lack of previous work on New Zealand-specific, deployment-grounded dilemmas, a new dataset was needed. Previous attempts to create more complex agentic simulations proved too difficult to get clean differences of value-based decisions (see \ref{app:simulation}). Specifically, it was found too time-consuming and resource-intensive to create simulations in which a clear dilemma was presented in a way that was easy to understand, classify and judge by the general public. Therefore, when writing the dilemmas, it was important to ensure that the value trade-off being tested was clear and unambiguous.

Ten different \term{work-profile}s were created with three dilemmas each. Each dilemma was a variation of a similar trade-off. The profiles, their reference documents and the thirty dilemmas are listed in \ref{sec:dilemma-profiles}. The decision about which work profile to use was based on two things:
\begin{enumerate}
    \item Deployment scenarios that could plausibly exist in the future and that cover a wider range than simply chatbot assistants.
    \item A work profile that has the potential to create high-quality dilemmas (easy to read, with each option equally defensible).
\end{enumerate}

Many dilemmas and work profiles were brainstormed by me with support from Ben Cravens and AI agents. Whether the work profiles had sufficient coverage of the New Zealand context was a human judgement call. Each dilemma also had to be readable, which was determined through feedback from the team.

To test whether the dilemmas had the potential to be decisive, a \scare{spot check} was done by running five samples from each of six frontier model providers (Cohere, OpenAI, Anthropic, Mistral, DeepSeek, Z.ai). By comparing the stability of the responses and the divergence between the models, we could see if a dilemma was likely to be decisive. This was done because early testing commonly showed that all models gave the same response—even if human readers thought the dilemma seemed equal. This was important because if all \scare{reasonable people} responded in the same way, then there would be no meaningful divergence to compare between the base and fine-tuned models. Crucially, the base and fine-tuned models were not used in this spot check, to ensure that cherry-picking divergent dilemmas did not happen, because this would undermine the validity of \rqref{align}.

A brainstorming process was used, and four work profiles were selected. One dilemma was written for each of them. These were iterated on using spot checks and human judgement until they were divisive and had clear value trade-offs. Next, frontier AI models were used to generate additional situations and work profiles. The generated ones were manually filtered and then iterated on until the target was reached.

\section{Analysis}
\label{sec:dilemmas-analysis}

This chapter asks whether the fine-tuned models are behaviourally different from the base model and, if so, which dilemmas are the most interesting.

\subsection{Classifying the model responses with a judge model}

Before any quantitative analysis can take place, each response has to be classified into one of the two answer categories (or the catch-all \texttt{Other}). An LLM-as-Judge model (\judgemodel{}) was used for this classification. The judge was given the situation, the question, the answer options, the model's response and reasoning. The categories are the two answer options written into each dilemma. Standard LLM-as-Judge methods were used \cite{zhengJudgingLLMasaJudgeMTBench2023, liuGEvalNLGEvaluation2023, guSurveyLLMasajudge2026}: structured output against a fixed answer schema and a temperature of 0. The judge does not have access to the model's system prompt, so it cannot use its knowledge of the work profile to classify the response. \subsection{Using a Monte Carlo permutation test to measure divergence}

As specified in the pre-registration \cite{thompsonPreregistrationAligningLLMs2026/10/1515:17}, the model response classifications were analysed using a Monte Carlo permutation test to measure the significance of the divergence between the base and fine-tuned models.

The test of divergence for each dilemma was performed by taking the counts of each model's response classifications (e.g., Model A had 24 option A, 23 option B and 3 other, while Model B had 12 option A, 15 option B and 3 other) and calculating the total variation distance (TVD) between the two distributions. This is a one-sided test; the null hypothesis is that the observed variation in TVD is due to chance. To build the null distribution for each dilemma, the counts are pooled and 10,000 permutations are drawn that assign the model labels randomly to each response. To calculate the p-value for each dilemma, we count how many of the permutations have a TVD greater than or equal to the observed TVD. The p-value is then calculated as follows:

\begin{align}
    p_d = \frac{1 + \#\{r : \mathrm{TVD}^{*}_{d,r} \ge \mathrm{TVD}_d\}}{10{,}001}
\end{align}

\noindent Here, $\mathrm{TVD}_d$ is the observed TVD for dilemma $d$, $\mathrm{TVD}^{*}_{d,r}$ is the TVD for dilemma $d$ in the $r$-th permutation and $\#$ is the count of elements in a set.


The overall test of divergence ($p_{\text{overall}}$) between the base model and the fine-tuned model involves counting how many times one of the 10,000 permutations has a mean divergence greater than or equal to the observed mean divergence. This gives a p-value for the overall test of divergence.
\begin{align}
    \overline{\mathrm{TVD}} &= \frac{1}{30}\sum_{d=1}^{30} \mathrm{TVD}_d\\
    \overline{\mathrm{TVD}}^{*}_r &= \frac{1}{30}\sum_{d=1}^{30}\mathrm{TVD}^{*}_{d,r}\\
    p_{\text{overall}} &= \frac{1 + \#\{r : \overline{\mathrm{TVD}}^{*}_r \ge \overline{\mathrm{TVD}}\}}{10{,}001}
\end{align}

\noindent Note that, due to the nature of the permutation test, the p-value is bounded by the number of permutations. In this case, with 10,000 permutations, the p-value is bounded at $1/10{,}001 \approx 0.0001$.

The p-values are then corrected to control the false discovery rate when performing multiple significance tests using the Benjamini-Hochberg procedure. The per-dilemma p-values are corrected within a model across the 30 dilemmas; the overall p-values are corrected across the four models.

There are technically three response options for each dilemma; the third is a catch-all for responses that cannot be mapped to either main category. The \texttt{Other} category is uninformative for comparing the two models, so a sensitivity analysis was done to see whether the results change when it is included or excluded.

Importantly, the permutation test is non-parametric and therefore does not assume a particular parametric distribution. However, it does make assumptions: under the null, the responses from the two models must be exchangeable, and the individual samples must be independent. These assumptions are reasonably well satisfied. For the overall test, there is an additional assumption that the dilemmas are independent of each other. This assumption is not fully met, because some dilemmas share the same work profile and describe similar situations with different details. The test should therefore be treated as approximate; a profile-level sensitivity analysis would check whether the dependence changes the conclusion.

\subsection{LLM-as-Judge scoring of the potential comparisons}

Given the use of the comparisons in \ref{chap:survey}, it was important to have a measure of the quality of the comparisons. Comparing almost identical responses would not be interesting, and neither would comparing models that made similar decisions. We used an LLM-as-Judge ensemble to develop a scoring system for measuring the quality of the comparisons. The scoring system was based on three metrics: value divergence, survey quality and interest to the New Zealand public. However, after initial testing only the value divergence metric was used for ranking. Each judge was given a prompt that included the dilemma, the base model response and the fine-tuned model response. Each judge was then asked to score the value divergence (among other things) on a scale of 1--5. The prompt can be seen in \ref{sec:dilemma-judge-prompt}.

To reduce instability, an ensemble of three models was used: \modelref{gpt-6-luna}, \modelref{claude-haiku-5.5} and \modelref{deepseek-v4.1-flash}.

When generating the comparisons for the survey, only sample-index-matched pairs were used. This decision was made because the cross product of all responses would be too large and would include duplicate responses. Therefore, some pairing is needed, and index matching is the most straightforward method, even if it is arbitrary. This was pre-registered to prevent cherry-picking pairs, given that one could reasonably pair one sample with any of the 50 samples from the other model.

\section{Results}
\label{sec:dilemmas-results}

The results of this chapter are based on the analysis of the model responses to the dilemmas. The two most important results are which model diverges most from the base model and which dilemmas are the most interesting.

\subsection{All models are divergent yet some more than others}

Four different fine-tuned models were tested against the base model. In \tabref{dilemmas-h1-summary}, we can see that three of the four models have a similar level of divergence from the base model. \modelref{ft-modal} stands out as having the largest divergence from the base model. Given the pre-registered hypothesis \cite{thompsonPreregistrationAligningLLMs2026/10/1515:17} and analysis plan, we conclude that \rqref{align} is supported. The training on the survey data has created models that are sufficiently different in behaviour from the base model. Given that these models were only trained on abstract survey data and not on the dilemmas themselves, this is consistent with emerging evidence \cite{nieSurveytoBehaviorDownstreamAlignment2025}. It supports the notion that the fine-tuning process has instilled different values into the models and so, when in a new situation, the model will behave differently (as values drive behaviour).

By inspecting \tabref{ft-results-Qwen3.8-27B}, we can see that \modelref{ft-modal} has the highest training accuracy yet also the highest cross entropy and KL divergence on the WVS items. It fits the training data almost perfectly and moves the probability mass the most. A plausible explanation is that this is why it has the most divergent behaviour from the base model.

On the other hand, \modelref{ft-first-token} performs among the best on the training metrics (highest validation accuracy and lowest validation cross entropy) yet has the least divergence from the base model. There are a few possible explanations for this. One is that, given the probability mass has moved less than the other models, its responses are more likely to be closer to the base model \footnote{It isn't necessarily the case that this is a bad thing. It is quite plausible that the optimal response is one very close to the base model and so the other models are overfitting to the training data and moving away from the optimal response.}. The reduced amount of probability mass moved is due to the training objective—a real distribution—being close to the base model (whereas \modelref{ft-modal} is training to meet a one-hot encoded distribution) and to the single-token target providing less supervision per example than a full response string.

\subsection{Limitations}

The result that the models diverge in behaviour is limited in two ways. First, with only 30 unique dilemmas across 10 work profiles, the claim is limited to these dilemmas. Second, sampling noise remains because the number of samples per dilemma is finite (see \ref{sec:dilemma-run-parameters}). Larger samples would increase confidence. Increasing both the number of dilemmas and the number of samples would strengthen the results, but the time and resource constraints of this project did not allow this.

There are some further methodological limitations worth noting: errors in the classification of model responses, the contrived nature of the dilemmas (i.e., they are not real deployment scenarios), and the \term{value-action} gap, which means the value shift is measured indirectly through a noisy proxy.
